## 固定版本连续运行与验收

该工具按实际 `time.monotonic()` 计时，另保存真实 UTC 开始/更新/结束时间。`required_seconds` 固定为 **36000**。短运行只产生 `smoke_passed`；它不代表十小时验收。所有行情和绩效仍是合成模拟资料，真实市场验收保持 `not_run`。

在全部识别、执行及运行核心冻结后，使用项目外的新目录启动：

```sh
python3 -m runtime.soak --data-dir "/absolute/path/outside-library/soak-candidate" --duration-seconds 36000 --pace .25
```

该命令不打开网页、接入券商或调用模型。它用默认五个品种、全部84张规则图和 `RuntimePolicy`，持续生成跨会话合成行情直到实际时间窗结束。有限输入完成后空等不计为本工具的方案；生成器仍有后续行情时由实际时间决定结束。合成市场时间与运行的真实 UTC 时间分别记录。

每60秒原子持久化 `soak-status.json`，其中包含实际经过时间、接收/处理量、各类输出量、积压及峰值、资金核对、RSS/峰值RSS、磁盘余量、数据库大小、版本哈希、吞吐和 P50/P95/P99 时延。时延只保留最近10000个样本，资源观测只保留最近720个，故障/恢复的完整证据另外追加到 `soak-faults.jsonl`。采样当前RSS默认预算1024MiB；峰值RSS另行记录。后段增长检查按样本数量取第二四分位区间与最后四分位区间的当前RSS中位数，差值默认不超过128MiB；该固定窗口不自动证明缓存已饱和或已进入稳定期。候选5使用原预算，失败结果不因后续诊断而改写。若调整参数，必须作为新的测试配置重新记录和运行，不能追溯修改原验收。

默认每900秒轮流执行以下故障，十小时内每一类会重复：重传原事件（新arrival仍不重复处理）、300条原始事件先落库再集中处理、断开/恢复来源并投递恢复前的旧报价、提交前故障、提交后故障、检查点后关闭并重建运行器。故障保留具体序号、实际发生时间、恢复耗时和断言结果。已有持仓与待退出保持真实状态；没有有效报价时不会伪造成交。

本工具的提交边界故障为 Python 异常，恢复在同一 OS 进程里关闭并重建 Runner；它不等于突然杀进程或断电测试。持久积压注入没有经过后台采集队列，不能证明队列溢出处理。断线注入核对当次成交量不增加，但不强制当时存在活动订单；待入场、真实停牌和待退出等具体执行边界由 paper 独立回归提供证据。Alpaca 网络、日历、认证与真实交易日历也不经过这条合成源。完整交付应分别记录这些测试层次，不能将十小时结果扩展为全部外部故障已经验收。

每次检查都核对成交和账本事件ID唯一、一笔订单只成交一次、初始资本加所有 `balance_delta_cents` 等于当前余额、预约和锁定金额、五仓位限制、活动入场/退出唯一、识别与模拟历史上限及 SQLite 完整性。

运行期每次接收前和每个故障/检查点核对代码与来源规则。`recognition/evaluation/runtime/paper/connectors` 的 Python 核心、全部setup源文件、`schema/*.schema.json`、`requirements-runtime.txt` 及连接器依赖版本中任一变化都会使本次测试失败。不能换代码后继续累计同一份十小时时间；应保留失败目录，重新冻结并使用新目录启动。维护报告和工作台文档不属于执行核心哈希。

结束后导出完整 `soak-journal.jsonl`，在 `replay-verification/` 全新数据库按原序号、来源、事件ID、控制和时钟重放。比较全部派生记录流、最终识别器快照、模拟快照、资金及处理进度；只比较账户余额不足以通过。验证时间单独保存，不用于填补运行观察时间。
